## 四、常见 Q&A 准备

### Q1：为什么不用 LSTM/GRU？

> "LSTM 在金融高频数据上容易过拟合，因为金融数据的信噪比极低，时序依赖不是简单的马尔可夫结构。ResidualMLP 更轻量，残差结构提供非线性能力同时保持训练稳定。对比实验中，同等参数量下 LSTM 的验证损失波动更大，早停触发的 epoch 也更早。"

### Q2：R² 只有 0.003，是不是模型不行？

> "金融高频数据中信噪比极低，这是领域常态。fret12 的不可预测成分很大（微观结构噪声、信息冲击），业界顶级方案 R² 也鲜有超过 0.01。Pearson 相关系数才是量化交易的核心指标，我们的 6.43% 已经达到课程预期。"

### Q3：62 个特征有没有过拟合风险？

> "我们有三层防护：第一，训练集和评估集在时间上完全分离（6-11 月 vs 12 月），不存在数据泄露；第二，验证集按时序切分而非随机，模拟真实部署场景；第三，消融实验显示所有 7 类特征都有正向贡献，不是靠凑特征数量刷分。最终评估集的 Pearson（6.43%）与验证集（约 6.5%）接近，说明泛化良好。"

### Q4：模型是在哪里训练的？演示时为什么这么快？

> "训练在同学的 RTX 4060 GPU 上完成，耗时约 15 分钟。演示时加载的是预训练权重，跳过训练直接推理。推理只需要前向传播，150 万条数据分批处理约 30 秒完成。模型通过 `torch.device` 自适应 GPU/CPU，评分老师用 CPU 机器也能正常运行。"

### Q5：AI 辅助的边界在哪里？

> "AI 辅助了样板代码（训练循环模板、torch.save 调用）、文档排版、可视化脚本框架。核心技术决策——特征体系框架、网络架构设计、标签缩放方案、时序验证方案——均由小组成员提出和决策。我们总结了一套 'AI 提议 → 人工审核 → 实验验证' 的三阶段范式，AI 提供候选广度，人提供逻辑深度，实验提供客观筛选。"

### Q6：如果给更多时间，还能优化什么？

> "三个方向：第一，引入 Transformer 的自注意力机制捕获跨股票和跨时间的复杂依赖；第二，增加更多另类数据源（如新闻情绪、宏观经济指标）；第三，使用集成学习方法（多个不同架构模型的预测平均）。但这些都受限于课程提交截止时间。"

## 五、应急预案

### 场景 A：程序运行报错

**最常见原因**：
1. `archive/` 路径不对 → 修改 `meow.py` 第 44 行的 `h5dir` 参数
2. 缺少依赖 → `pip install torch scikit-learn pandas tables numpy`
3. `resources/calendar` 文件缺失 → 检查文件是否存在

**应对**：课前试跑确保无误。如果现场出问题，直接展示已有的终端截图/录屏。

### 场景 B：运行太慢（>2 分钟）

**应对**：
- 提前说"现场用 CPU，需要等待一会儿"
- 准备一份已运行完的终端输出截图作为备用
- 等的时候可以继续讲其他内容（如展示代码结构）

### 场景 C：投影仪分辨率低看不清终端

**应对**：
- 提前调大终端字体（Ctrl+Plus）
- VS Code 字体也调大
- 关键数字直接口播，不依赖屏幕阅读

### 场景 D：时间不够被催

**应对**：按优先级裁剪：
1. **必须保留**：现场运行 + 结果展示（步骤 3+4）
2. **可压缩**：代码结构速览（步骤 2、6 合并为快速 scroll）
